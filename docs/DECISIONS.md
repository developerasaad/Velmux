# Velmux — Decision Log

Historical engineering decision record (D-001 …). Entries up to the
repository restructure describe the pre-Kotlin React Native
architecture; their reasoning about pins, platforms and media behavior
remains the context for the decisions that still apply. Current
architecture: docs/ARCHITECTURE.md.

Append-only decision log. Escalate conflicts; never silently change settled
decisions without evidence.

| D-026 | 2026-11-23 | Apple hardware probing uses only iOS-portable APIs: VTCopyVideoEncoderList + kVTVideoEncoderList_IsHardwareAccelerated for encode, VTIsHardwareDecodeSupported for decode (VP9) | VTIsHardwareEncodeSupported does not exist in iOS SDKs (macOS-only; verified against the iPhoneOS16.5 SDK headers) — it broke the iOS build. | D-027 | 2026-11-23 | android.yml/ios.yml consume the velmux-ffmpeg-android/ios artifacts from the latest successful ffmpeg-mobile run on main (push events; honest no-FFmpeg fallback with a warning) | M3 wiring: the shipped apps must carry the real FFmpeg backend. | D-028 | 2026-11-23 | Hybrid (M4) v1: the CPU video frame (Yuv420P) is the ONLY cross-backend object; compressed data never crosses backends; audio only stream-copied by the muxing side; no geometry/rate change; subtitle policy Remove only; no checkpoints (whole-pipeline executors keep that duty) | Encoder packets going straight into the same backend's muxer makes spec §31 bitstream incompatibilities structurally impossible; the planner generates hybrid candidates only when no single-backend transcode exists, so the copy cost is paid only for pipelines that would otherwise have no route |
| D-029 | 2026-11-23 | FFmpeg stage workers are new additive classes, not a refactor of the whole-pipeline executor | The whole-pipeline path carries the battle-tested M7 segmented recovery; extracting stages from it risks destabilizing recovery for zero behavioral gain. | D-030 | 2026-11-23 | All mobile FFmpeg static libraries build PIC; FFmpeg's C flags add -fvisibility=hidden | The first FFmpeg-wired Android link failed: libmp3lame tables (no --with-pic) and FFmpeg NEON asm's direct ADRP against default-visibility symbols are invalid in a shared library. | D-031 | 2026-11-23 | Trimmed transcoded output keeps source-timeline timestamps (spec §20 matched-source-timestamp comparison); stream-copied trims snap their start to the keyframe at/before the boundary | Re-timing compressed data requires re-encoding; MP4 edit lists absorb nonzero starts for playback. | D-032 | 2026-11-23 | Sample generation plans against the FULL source, then executes only the densest window; representative = max per-second compressed bytes over a sliding window (demux-level, single pass, no decode) | The preview must show exactly what the real job would produce (goal-derived quality, budgets); bytes/second is an honest motion/detail proxy without decoding. | D-033 | 2026-11-23 | Job store schema v2 adds trim_start_us/trim_end_us via ALTER TABLE (appended columns; positional SELECT * reads stay valid) | executeJob reloads the request from SQLite; the v1 schema silently dropped the trim on the submit→reload round-trip (caught locally: a 4s source produced a 4s 'trimmed' output) |
| D-034 | 2026-11-23 | Hybrid muxer audio: save source timing, av_packet_move_ref, THEN rescale/overwrite | av_packet_move_ref copies the whole AVPacket struct; values computed before it are clobbered (AAC sample counts written as ms → 89s output for 2s of media) |
| D-035 | 2026-11-23 | M8 Android: the engine is process-owned (EngineHolder), never destroyed on React teardown; a dataSync foreground service renders aggregate live progress + terminal notifications and self-stops when the engine idles | Spec §22 requires the job engine to be independent of RN; the engine is a C++ library in the process, so the process living = the engine running. | D-036 | 2026-11-23 | Event pump lifetime is state-driven: run while listeners exist OR work is active; exit after ~12s fully idle; restart on demand | A request/release counter protocol leaks on RN teardown mid-job (activity destroyed before completion) and would keep a 250ms poll alive forever; the idle exit is self-healing and wake() covers restarts |
| D-037 | 2026-11-23 | M8 iOS: BGProcessingTask retries only INTERRUPTED jobs; user-PAUSED jobs stay paused | INTERRUPTED means the OS/user killed the process mid-job — the user's original intent stands, so resuming preserves their work (spec §4.5). | D-038 | 2026-11-23 | iOS notifications post only when the app is NOT active; Android terminal notifications always post (channel-gated) | On iOS the foreground app IS the active surface — duplicate banners would be noise; Android's channel system already gives the user the control |
| D-039 | 2026-11-23 | Subtitle extraction implemented (supersedes D-013): subtitle-only requests extract the FIRST text track to a sidecar (native SRT/WebVTT/ASS copied, mov_text/ttml decoded to SRT); sidecar minimum size is 32 bytes with cue-structure validation | The extraction primitive (demux+packet copy) already existed for burn-in offset materialization. v1 extracts one track because the job model records one output artifact; the summary says "track 1 of N" when more exist. | D-041 | 2026-11-23 | Trim-aware duration validation: the expectation subtracts the active trim window (+1s tolerance for the stream-copy keyframe snap) | With D-040 live, the validator compared trimmed outputs against the FULL source duration and failed every trim job by design; the expectation must describe what a CORRECT output looks like for the actual request |
| D-042 | 2026-11-23 | Fit-under-size DRIVES execution: the budget-derived bitrate becomes the effective rate control before planning (pure function of source+request, deterministic on retry); one corrective re-encode at 0.9x(target/actual)x base bitrate when the first attempt overshoots; a still-missed target completes with an honest pipeline-summary note | The budget was advisory before: nothing parameterized the encode toward the target (spec compression intelligence). | D-043 | 2026-11-23 | Audio DSP (gain/fades/loudnorm/atempo/silenceremove) runs as an abuffer->abuffersink graph between decode and the resampler; the sink is pinned to the decoder's negotiated format/rate/layout so the swr config stays valid; an AVAudioFifo between resampler and encoder absorbs the frame-size mismatch (AAC requires exactly frame_size samples per non-final frame) | The old direct path only ever saw decoder-sized frames; DSP graphs emit arbitrary chunk sizes. | D-044 | 2026-11-23 | Bitmap burn-in (PGS/DVB/VobSub): cues pre-decoded into full-geometry YUVA420P overlay frames, composited through a manually-linked overlay filter graph; text burn-in keeps libass; combining bitmap cues with crop/rotation/flip refuses honestly | libass cannot render bitmaps. | D-062 | 2026-11-25 | File-access model: NO storage permissions anywhere.
