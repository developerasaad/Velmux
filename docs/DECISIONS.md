# Velmux — Decisions

Append-only decision log. Escalate conflicts; never silently change settled
decisions without evidence.

| ID | Date | Decision | Rationale |
|---|---|---|---|
| D-001 | 2026-11-21 | Monorepo with `core`, `backends/*`, `bridge`, `apps/mobile`, `tools/ffmpeg-builder` | Single canonical repo; C++ core reusable independent of RN |
| D-002 | 2026-11-21 | doctest for C++ unit tests | Header-only, fast compile, readable assertions; sufficient for core unit testing |
| D-003 | 2026-11-21 | Android min API 29 (Android 10) | Per spec; MediaCodec/AMediaExtractor surface stable at 29 |
| D-004 | 2026-11-21 | iOS deployment target 15 | VideoToolbox/AVFoundation APIs used by Velmux are stable on 15; Swift concurrency available; lowest sensible target for the architecture. Revisit if a required API demands higher |
| D-005 | 2026-11-21 | FFmpeg pinned at 7.1.x release line (see tools/ffmpeg-builder/versions.json) | Current stable LTS-line; contains all required codecs/filters; pinned by tarball + SHA-256 |
| D-006 | 2026-11-21 | FFmpeg consumed as libraries only; CLI never used for production conversion | Spec §29; capability manifest generated from actual build |
| D-007 | 2026-11-21 | Whole-pipeline executors allowed when one backend serves every stage of the best candidate; stage-composed hybrid execution targeted for M4 | Pragmatic vertical slice while keeping stage interfaces real |
| D-008 | 2026-11-21 | SQLite for durable job state; schema versioned, forward migrations | Spec §24; system lib on host, bundled on mobile |
| D-009 | 2026-11-21 | Host (Linux) builds of core + FFmpeg backend in CI as fast signal; Android emulator/instrumented tests and iOS simulator tests on their respective runners | Linux cannot build Apple projects; CI is authoritative cross-platform validation |
| D-010 | 2026-11-21 | Independent output validation: core validator + external ffprobe cross-check in integration tests | Spec §50: never validate output only with the code that produced it |
| D-011 | 2026-11-21 | External dependency pins recorded with SHA-256 checksums at first fetch (TOFU), documented for maintainer cross-check against upstream signatures | Reproducibility without pretending offline trust anchors exist |
| D-012 | 2026-11-21 | React Native app initialized from the community CLI template (New Architecture: Fabric/TurboModules on) | Spec §6 requires modern architecture |
| D-013 | 2026-11-22 | Subtitle EXTRACT policy is rejected by the planner (honest infeasibility) until sidecar extraction is implemented; Preserve/Remove/BurnIn are fully implemented and tested | Never silently drop streams (spec §14); fail loudly instead |
| D-014 | 2026-11-22 | Burn-in styling: SRT-like sources get force_style redirected to the discovered local font family (hermetic static builds have no system font provider); ASS/SSA keep authored styling | libass can only match fontsdir fonts by family without a provider; authored ASS styles (with embedded fonts) must not be overridden |
| D-015 | 2026-11-22 | Burn-in never stream-copies video (planner-enforced, executor-defended): subtitle rendering rewrites pixels | Correctness over speed; remux cannot burn |
| D-016 | 2026-11-22 | iOS harfbuzz builds with CoreText disabled: upstream 10.2.0's CMake port never defines HB_IOS, so the CoreText branch is dead and the macOS fallback records no frameworks | harfbuzz's internal shaper (what libass drives) is unaffected; revisit if harfbuzz moves to Meson |
| D-017 | 2026-11-22 | Recovery segments: finalized-and-committed 10s transcode pieces with contiguous-prefix resume; segment runs warm the decoder up from the post-seek keyframe and discard only decoded frames before the boundary | The decoder must see the keyframe: dropping pre-boundary packets at the demux level makes every segment not starting exactly on a keyframe decode zero frames; prefix contiguity (validated on resume, suspicious gaps rejected) is what makes assembled output cover the full source |
| D-018 | 2026-11-22 | Checkpoint rows survive every job-state persist (updateJob replaces only the jobs row); explicit cleanup on completion, cascade on job deletion | updateJob's delete+insert cascade wiped committed checkpoints on cancel/pause/retry — destroying exactly the resume data those transitions rely on |
| D-019 | 2026-11-22 | Checkpoint sequences continue after the persisted per-job maximum across runs | (job_id, sequence) is UNIQUE; restarting at 1 collides with surviving rows from earlier runs |
| D-020 | 2026-11-22 | Worker liveness is a first-class query (VelmuxEngine::isJobActive, bridge + TurboModule) | Durable state flips to Canceled/Paused immediately (control path) while the executor may still be unwinding; hosts and tests need the deterministic "cancel completed" signal — progress events carry the terminal state and cannot provide it |
| D-021 | 2026-11-22 | Final assembly of committed segments stream-copies through the concat demuxer with safe=0 | Segments are core-generated validated artifacts at core-generated paths; the demuxer's safe mode exists for untrusted user lists. Chaining by each segment's actual duration keeps A/V alignment without re-encoding |
| D-022 | 2026-11-22 | libvpx sim-arm64 builds with the arm64-darwin20-gcc target | arm64-darwin-gcc hard-overrides CC/CXX/AS/LD with the iphoneos (device) toolchain inside configure, ignoring the environment; the versioned darwin20 target walks the same flag path but respects the env wrappers whose trailing SDK re-assertion wins conflicts |
| D-023 | 2026-11-22 | Android transcode uses the zero-copy surface path (decoder renders into the encoder's input surface) | No YUV layout wrangling (flexible-format parsing is fragile across vendors), no intermediate copies, the standard production transcode topology; audio stays on the ByteBuffer PCM path |
| D-024 | 2026-11-22 | BackendCapabilities gained videoScaling/audioResampling/subtitlePassthrough/subtitleBurnIn; the planner enforces them per request+source | The planner owns policy (spec §32): geometry/audio-format changes and subtitle work only route to backends that implement them; the executor double-checks. Native M1 honestly reports false for all four |
| D-025 | 2026-11-22 | libvpx iOS sim-x86_64 uses x86_64-iphonesimulator-gcc | darwin18 injects -mmacosx-version-min + the MacOSX sysroot, which clang rejects outright when combined with the simulator min-version; the official simulator toolchain injects compatible flags that the wrapper's trailing re-assertion overrides |
| D-026 | 2026-11-23 | Apple hardware probing uses only iOS-portable APIs: VTCopyVideoEncoderList + kVTVideoEncoderList_IsHardwareAccelerated for encode, VTIsHardwareDecodeSupported for decode (VP9) | VTIsHardwareEncodeSupported does not exist in iOS SDKs (macOS-only; verified against the iPhoneOS16.5 SDK headers) — it broke the iOS build. AVAsset.startTime is likewise not an iOS API; the writer session starts at the earliest track timeRange start |
| D-027 | 2026-11-23 | android.yml/ios.yml consume the velmux-ffmpeg-android/ios artifacts from the latest successful ffmpeg-mobile run on main (push events; honest no-FFmpeg fallback with a warning) | M3 wiring: the shipped apps must carry the real FFmpeg backend. Artifacts download into tools/ffmpeg-builder/out/{android,ios} so the pkg-config files' baked absolute runner paths stay valid |
| D-028 | 2026-11-23 | Hybrid (M4) v1: the CPU video frame (Yuv420P) is the ONLY cross-backend object; compressed data never crosses backends; audio only stream-copied by the muxing side; no geometry/rate change; subtitle policy Remove only; no checkpoints (whole-pipeline executors keep that duty) | Encoder packets going straight into the same backend's muxer makes spec §31 bitstream incompatibilities structurally impossible; the planner generates hybrid candidates only when no single-backend transcode exists, so the copy cost is paid only for pipelines that would otherwise have no route |
| D-029 | 2026-11-23 | FFmpeg stage workers are new additive classes, not a refactor of the whole-pipeline executor | The whole-pipeline path carries the battle-tested M7 segmented recovery; extracting stages from it risks destabilizing recovery for zero behavioral gain. Shared helpers moved to ffmpeg_util.h; the duplication is the stage-level setup only |
| D-030 | 2026-11-23 | All mobile FFmpeg static libraries build PIC; FFmpeg's C flags add -fvisibility=hidden | The first FFmpeg-wired Android link failed: libmp3lame tables (no --with-pic) and FFmpeg NEON asm's direct ADRP against default-visibility symbols are invalid in a shared library. Hidden visibility makes the C symbols non-preemptible, which legalizes the asm's relocations |
| D-031 | 2026-11-23 | Trimmed transcoded output keeps source-timeline timestamps (spec §20 matched-source-timestamp comparison); stream-copied trims snap their start to the keyframe at/before the boundary | Re-timing compressed data requires re-encoding; MP4 edit lists absorb nonzero starts for playback. Recovery segments already use the source timeline, so trim windows compose with the checkpoint coordinate system unchanged |
| D-032 | 2026-11-23 | Sample generation plans against the FULL source, then executes only the densest window; representative = max per-second compressed bytes over a sliding window (demux-level, single pass, no decode) | The preview must show exactly what the real job would produce (goal-derived quality, budgets); bytes/second is an honest motion/detail proxy without decoding. No durable job, no checkpoints: samples are bounded, regenerable previews; cancellation stays unwired in v1 (documented) |
| D-033 | 2026-11-23 | Job store schema v2 adds trim_start_us/trim_end_us via ALTER TABLE (appended columns; positional SELECT * reads stay valid) | executeJob reloads the request from SQLite; the v1 schema silently dropped the trim on the submit→reload round-trip (caught locally: a 4s source produced a 4s 'trimmed' output) |
| D-034 | 2026-11-23 | Hybrid muxer audio: save source timing, av_packet_move_ref, THEN rescale/overwrite | av_packet_move_ref copies the whole AVPacket struct; values computed before it are clobbered (AAC sample counts written as ms → 89s output for 2s of media) |
| D-035 | 2026-11-23 | M8 Android: the engine is process-owned (EngineHolder), never destroyed on React teardown; a dataSync foreground service renders aggregate live progress + terminal notifications and self-stops when the engine idles | Spec §22 requires the job engine to be independent of RN; the engine is a C++ library in the process, so the process living = the engine running. The service's Cancel action calls the engine directly (works without the RN UI, spec §23) |
| D-036 | 2026-11-23 | Event pump lifetime is state-driven: run while listeners exist OR work is active; exit after ~12s fully idle; restart on demand | A request/release counter protocol leaks on RN teardown mid-job (activity destroyed before completion) and would keep a 250ms poll alive forever; the idle exit is self-healing and wake() covers restarts |
| D-037 | 2026-11-23 | M8 iOS: BGProcessingTask retries only INTERRUPTED jobs; user-PAUSED jobs stay paused | INTERRUPTED means the OS/user killed the process mid-job — the user's original intent stands, so resuming preserves their work (spec §4.5). PAUSED is an explicit decision; auto-resuming it would override the user |
| D-038 | 2026-11-23 | iOS notifications post only when the app is NOT active; Android terminal notifications always post (channel-gated) | On iOS the foreground app IS the active surface — duplicate banners would be noise; Android's channel system already gives the user the control |
