# Velmux v0.1.0-rc.1 — Release Candidate 1

First distributable release candidate. This is a **release candidate, not a
validated stable release**: emulator and CI validation are broad, physical-device
validation is not yet complete. See "Pending hardware validation" below.

## What this build contains

**Engine (shared C++ core)**
- Feature registry (product-controlled V1 media matrix) + capability registry
  (per-device, per-backend), deterministic whole-pipeline planner with cost
  model, hybrid (cross-backend) pipeline planning.
- Job lifecycle with durable SQLite persistence (schema v2 with forward
  migration), resource-aware scheduler (CPU/memory/thermal/battery/hardware
  codec scarcity), segmented recovery with crash-safe checkpoint commits and
  durable resume, independent output validation (never trusts the executor's
  own success), event bus, telemetry store.

**Backends**
- FFmpeg 7.1.1 (pinned sources, SHA-256 verified, built by
  `tools/ffmpeg-builder`): full transcode/remux/trim/resolution/fps
  conversion/subtitle preserve+burn-in+extraction path, checkpointed
  segmented recovery for long jobs, sample generation.
- Android: MediaCodec surface-path transcode, MediaExtractor inspection,
  MediaMuxer remux, MediaCodecList capability reporting.
- Apple: VideoToolbox/AVFoundation transcode (iOS-portable hardware probes),
  AVAssetExportSession remux, inspection.
- Hybrid execution: cross-backend pipelines through Yuv420P CPU-frame
  interchange (FFmpeg stages proven end-to-end in CI; native stage workers
  land post-RC1).

**App (React Native 0.88, New Architecture)**
- Home/Convert/Queue/History/Settings; goal presets (Recommended, Smaller
  File, High Quality, Fit Under Size, Custom), advanced controls (hidden by
  default, preserved on close, "Custom — based on [preset]" behavior),
  live plan estimates, durable SAF document access.
- Android: process-owned engine, foreground service with progress
  notifications + Cancel action, terminal notifications.
- iOS: BGProcessingTask resume for interrupted jobs, background-task window,
  local notifications when backgrounded.

## Tested platforms (automated, in CI)

- Host (Linux): full engine + FFmpeg backend + bridge test suite, including
  real-file conversion tests with independent ffprobe cross-validation,
  fault-injected cancel/resume recovery, truncated/disappearing-source and
  unwritable-destination hardening tests. All green.
- Android: debug APK builds with the real FFmpeg backend linked; instrumented
  tests (real MediaCodec transcode/remux/inspection, independent
  MediaExtractor validation) run on x86_64 AOSP emulators at API 29 and 34.
- iOS: Debug and Release configuration simulator builds with the real FFmpeg
  backend linked (CocoaPods + xcframework).

## Pending hardware validation (not claimed as verified)

- Physical Android devices: MediaCodec surface path across vendor encoders,
  foreground-service behavior under real process lifecycle, notification UX.
- Physical iPhones / Apple Silicon: VideoToolbox encode behavior,
  BGProcessingTask scheduling, notification behavior. iOS engine execution
  has not been validated on hardware; simulator runtime execution of the
  engine is scheduled next.
- Hybrid pipelines with a native side (N→N, F→N, N→F): the architecture and
  FFmpeg↔FFmpeg proof exist; native stage workers are post-RC1 work.
- True storage-exhaustion (ENOSPC) testing; process-kill restart E2E on
  devices.

## Known limitations

- Hybrid jobs are not checkpointed (restart from zero on retry); whole-
  pipeline FFmpeg jobs keep segmented recovery.
- Bitmap subtitle burn-in (PGS/VobSub/DVB) and CEA-608/708 extraction are
  not implemented; these formats are refused honestly, never silently
  dropped. PGS/VobSub → SRT OCR is out of V1 scope by specification.
- Android/iOS native executors do not honor trim windows yet; the planner
  routes trimmed requests to FFmpeg only (never silently untrimmed output).
- Fit-under-size compression is advisory (budget math + planner warning);
  no automatic second-pass re-encode yet.
- Batch/multi-file UI is not present; the scheduler and engine support
  queued jobs.

## Signing status of these artifacts

- Android APK/AAB are signed with the **debug keystore** (test-signable)
  unless CI release secrets are configured. Store distribution requires a
  private release keystore — see `docs/RELEASE.md`. The builds are genuine
  release builds (R8-minified, non-debuggable, native FFmpeg linked).
- iOS artifacts are **unsigned**: a simulator .app and an unsigned device
  .app suitable for later re-signing/archiving. No App Store or ad-hoc
  distribution is possible without an Apple Developer certificate.
