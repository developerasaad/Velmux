# Velmux v0.1.0-rc.2 — Release Candidate 2

Second release candidate. This is still a **release candidate, not a validated
stable release**: host, emulator and simulator validation are broad; physical-device
validation is not yet complete. See "Pending hardware validation" below.

## What changed since rc.1

**Engine (shared C++ core)**
- HEVC software encode through FFmpeg (pinned libx265 3.6) — the full V1 codec
  matrix no longer depends on native encoders for HEVC.
- Multi-track audio: `allTracks` carries every source lane with its language
  metadata; external audio replacement paced onto the video timeline.
- Cover art: external image attach (attached_pic disposition) and source
  picture preservation.
- HDR: explicit `ToneMapToSdr` (colorspace → BT.709 with SDR output tagging)
  plus automatic tone-mapping when the output path cannot carry HDR; stream
  copy preserves HDR signaling untouched.
- CEA-608/708 detection at inspection (A53 side-data probe; feeds the planner's
  "transcoding drops captions" advisory).
- Metadata strip option; container/stream metadata preserved through transcode
  and remux by default.
- Runtime failure feedback: execution-attributable backend failures record a
  narrow configuration key with a cooldown; the planner avoids live-failed
  routes (proven by engine test: record → reroute → narrowness).
- True ENOSPC mapping: full-disk writes surface as terminal `StorageFull`
  (output writes and subtitle sidecars alike), never retried or truncated.
- Platform resource feeds: Android ConversionService and iOS VelmuxEngineHost
  push debounced thermal/battery/memory state into the resource-aware
  scheduler while work is active.
- Native stage workers for hybrid pipelines (Android ImageReader/MediaCodec,
  Apple reader/writer stages) composed through the same HybridExecutor;
  emulator/device execution via the masked-engine instrumented tests.

**App (React Native)**
- Trim UI (start/end steppers with mm:ss display and window summary),
  sample-compression preview (8 s of the densest section at the current
  settings, invalidated on any draft change), batch multi-select conversion,
  history actions wired to real output files (share/play/delete, reuse
  settings).
- Full advanced-controls contract wired to the engine: profile, pixel format,
  bit depth, GOP, B-frames, HDR policy, metadata strip — on top of the
  existing codec/rate/fps/backend controls.
- Complete accessibility annotation pass (grouped row labels, control+value
  labels, job-scoped actions, announced states).

**Hardening (new host tests, all real conversions with independent ffprobe
cross-checks)**
- Non-monotonic PTS sources (backward jumps mid-stream) convert honestly or
  fail with a real error — never fake success, hang, or crash.
- ~600 KB container metadata payloads convert per request (preserve/strip)
  without truncation.
- Feature verification wave: multi-track, replace-audio, cover art, HDR
  tone-map/copy-preserve, HEVC encode, CEA negative — every advertised
  feature now has a REAL test.

**Build/test infrastructure (repository owns the build)**
- `./scripts/build.sh`, `./scripts/test.sh`, `./scripts/clean.sh` with
  per-platform internals; CI is a dumb executor (checkout → toolchain →
  scripts → upload).
- FFmpeg mandatory in every app build: resolve target → verify identity-
  matched artifact → reuse or rebuild → build Velmux; no "without FFmpeg"
  path exists.
- Artifact identity: platform/ABI/config/versions/toolchain hashes recorded
  in BUILD-IDENTITY and verified before reuse (host identity is
  platform-level so the CI-built dev prefix validates on any Linux x86_64).
- CI builds the canonical host FFmpeg and uploads it as an artifact;
  `scripts/ffmpeg/fetch-artifact.sh` installs it locally (identity- and
  completeness-gated).
- Emulator CI executes the instrumented suites on KVM emulators
  (API 29 + 34) with cold-launch, relaunch and recovery checks; iOS
  simulator suite runs the engine XCTest target via `./scripts/test.sh
  --ios-sim`.
- Linux runners pinned to ubuntu-24.04 (the moving ubuntu-latest broke the
  emulator); x265 3.6 CMake-4 compatibility patch; per-host fetch
  User-Agents; bash-3.2 (macOS) compatibility.

## Tested platforms (automated, in CI)

- Host (Linux): full engine + FFmpeg backend + bridge suite including real
  conversion tests with independent ffprobe cross-validation, fault-injected
  cancel/resume recovery, and the hardening matrix (truncated/disappearing
  source, unwritable destination, non-monotonic timestamps, huge metadata).
- Android: release APK + AAB with the FFmpeg backend linked (R8, resource
  shrinking); instrumented tests on x86_64 emulators at API 29 and 34.
- iOS: simulator build with the FFmpeg xcframework plus the engine XCTest
  suite; unsigned device build in Release configuration.

## Pending hardware validation (not claimed as verified)

- Physical Android devices: MediaCodec surface path across vendor encoders,
  zero-copy paths, foreground-service behavior under real process lifecycle,
  notifications, screen-off/thermal behavior, hybrid native↔FFmpeg runs.
- Physical iPhones: VideoToolbox encode behavior, BGProcessingTask
  scheduling, notification behavior.
- Genuine full-disk (ENOSPC) device run and real SIGKILL-restart E2E on
  devices (mapping and analogues are host-verified).

## Known limitations

- Hybrid jobs are not checkpointed (restart from zero on retry);
  whole-pipeline FFmpeg jobs keep segmented recovery.
- CEA-608/708 positive detection has no automated fixture (the pinned ffmpeg
  CLI cannot author A53 SEI); text extraction is out of V1 (OCR-class).
- The planner's cost model is deterministic scoring; measured-throughput
  learning (telemetry → planner) is not wired.
- VoiceOver/TalkBack behavior on physical devices is pending; the annotation
  pass is complete.

## Signing status of these artifacts

- Android APK/AAB are signed with the **debug keystore** unless CI release
  secrets are configured; the builds are genuine release builds (R8-minified,
  non-debuggable, native FFmpeg linked). See `docs/RELEASE.md`.
- iOS artifacts are **unsigned** (simulator .app + unsigned device .app
  suitable for later re-signing). No App Store or ad-hoc distribution
  without an Apple Developer certificate.

## FFmpeg build identity

Pinned sources and SHA-256 checksums: `tools/ffmpeg-builder/versions.json`
(hash recorded in the release `manifest.json`). libavdevice is intentionally
excluded; libraries are consumed directly, never through the CLI.
